## Endpoint

`POST /api/v1/merchant/:merchantId/products/:productId/duplicate` — `PRODUCT_MANAGE` (OWNER, MANAGER).

Body:

| Field | Rule |
| --- | --- |
| `requestId` | Required UUID generated by the client once per duplication attempt (reused on retry). Compared case-insensitively |
| `name` | Optional; trimmed, 1–255 characters (blank after trimming is rejected). When omitted: `Copie de <source name>` truncated to 255 |

Response: `201` with `{ product, replayed: false, copied }` for a new copy, `200` with `replayed: true` when the same `requestId` already produced a copy of the same source. `product` is the normal product detail of the copy; `copied` reports `{ optionGroupCount, optionCount, imageCopied }` (on replay, the counts of the existing copy). The request key itself is never returned.

## What is copied

| Copied (new ids) | Not copied |
| --- | --- |
| Branch and Category (same as the source) | Order items and order history |
| Name (default "Copie de …" or the submitted name), description, `priceMinor` | Ratings, reports, sales rankings |
| Option groups: name, required, min/max selections (required choices and optional extras) | Audit identity (`createdAt`/`updatedAt` are new) |
| Options: name, `additionalPriceMinor`, availability | Cart items |
| Photograph: bytes copied to a new `product-images/` object | `available` (the copy starts `false`) |

The source Product, its option groups, options and image row are read under `FOR SHARE` locks and never written. Copied groups and options keep the source order (strictly increasing `createdAt`).

## Atomicity

- The Product, option groups, options and image row are inserted in one database transaction. Any failure rolls back every row.
- Object storage is not transactional: the image bytes are copied to a new object before the transaction and that object is deleted if the transaction fails or loses a concurrent race. If the source has no image row, or its stored object is missing, the copy is created without an image and `copied.imageCopied=false`. If storage cannot be read or written, the request fails with `503 STORAGE_UNAVAILABLE` before any row is written.
- A replay is detected before any image copy, so a retried request never creates an object.
- Copies never share an object id with the source, so deleting or replacing either product's photo cannot remove the other's bytes.

## Retry and idempotency

There is no global client idempotency header (API conventions keep that open for business confirmation). This endpoint uses its own `requestId`:

- The copy stores `duplicate_request_key = sha256(sourceProductId + ":" + lowercase(requestId))` (hex, `varchar(64)`, unique). Products created any other way keep `NULL`.
- A retry with the same `requestId` and source finds the existing copy and returns it with `replayed: true` (no second copy). Concurrent identical requests produce one copy; the losers hit the unique index and replay (isolated e2e: three simultaneous taps → statuses 200, 200, 201 and one product).
- A new `requestId` deliberately creates another copy.
- A request that failed (rolled back) can be retried with the same `requestId` and then creates the full copy.

## Errors

| Situation | Response |
| --- | --- |
| STAFF | `403 MERCHANT_ROLE_FORBIDDEN` |
| Caller not a member of the Merchant | `404 MERCHANT_NOT_FOUND` |
| Product unknown, or its Branch belongs to another Merchant | `404 CATALOG_PRODUCT_NOT_FOUND` |
| `requestId` not a UUID; `name` blank or longer than 255 | `400 VALIDATION_ERROR` |
| Replay key exists on a product of another Branch (should not happen) | `409 CATALOG_DUPLICATE_REQUEST_CONFLICT` |
| Storage unreadable / unwritable | `503 STORAGE_UNAVAILABLE` |
| Unexpected database failure | `500 INTERNAL_ERROR`, no rows written, copied object discarded |

## Merchant UI

"Dupliquer le produit" (reference `duplicate_product_french`; its PNG is black, so `code.html` is the visual source): source card, editable new name prefilled with "Copie de …", copied-items checklist, the not-copied banner and the draft note. The screen generates one `requestId` when it opens and reuses it for every attempt from that screen. "Créer la copie" is disabled while the request runs and a second tap is ignored. On success the list refreshes and the editor of the new product opens; the copy is shown as unavailable. The product menu (with "Dupliquer") exists for OWNER and MANAGER only; STAFF has no product menu, and opening the duplicate route directly shows a forbidden state without a create button.
